# Quoridor Training Collapse Analysis

This document summarizes our investigation into the loss rate and representation collapse of the Quoridor AlphaZero agent, along with our recommendations for data handling and architectural fixes.

---

## 1. Key Findings

### A. Complete Model Collapse
We loaded and inspected the model weights from the current Epoch 95 checkpoint (`quoridor_checkpoint.pth`) and the backup Epoch 59 checkpoint (`backups/quoridor_checkpoint.pth`).
* **Identical Predictions**: The average pairwise cosine similarity of the predicted policy distribution across 3,570 different board states is **exactly `1.000000`**.
* **Constant Value**: The predicted value head outputs a constant scalar of `0.0035` with a standard deviation of `0.0001` across all inputs.
* **Fixed Bias Selection**: The network always outputs the same concentrated distribution favoring orthogonal moves (Action 0 / North at ~81.1%), completely ignoring wall placements and the board layout.

### B. Loss Stagnation & Zero Gradients
* **Policy Loss vs. Entropy**: Policy Loss has stagnated around `1.90 - 2.03` (which is almost exactly equal to the policy's predicted entropy).
* **Zero Gradients**: The gradient norm of the final policy layer `policy_fc` is **exactly `0.0`** during training. The optimizer has settled into a local minimum where the policy head only outputs the dataset's average target policy via the layer's bias weights.

### C. Self-Play "Feedback Loop of Death"
Our analysis of the self-play game files in the `data/` directory shows that:
* Early on (Epochs 11-81), the draw rate was low (**<8%**), and MCTS search was finding wins.
* However, because the policy network collapsed to always prioritizing "move North", the self-play games generated by the actors degenerated into pawns walking into walls, repeating moves, and triggering draw conditions.
* By Epoch 95, the draw rate reached **93.75%**. The model was trained entirely on games with 0.0 value targets and repetitive pawn moves, reinforcing the collapse.

---

## 2. Recommendations for Current Training Data

> [!IMPORTANT]
> **We recommend starting training completely from scratch (Epoch 0) and archiving/clearing the current `data/` directory.**

### Why we cannot resume from a checkpoint:
1. **Weight Shape Incompatibility**: The proposed fixes change the input shape of the CNN trunk (reducing channels from 11 to 6) and introduce new fully connected entry points. This breaks parameter shape compatibility with all existing `.pth` checkpoints.
2. **Replay Buffer Pollution**: The existing self-play games in the `data/` folder (especially from recent epochs) contain collapsed, low-quality trajectories. Training on this history would bias the new model towards pawn-only movements and draws.

---

## 3. Diagnosis & Proposed Fixes

### Root Cause 1: Constant 2D Input Planes
Tiling scalar features (distance, turn, walls remaining) as constant 9x9 channels creates a high amount of "activation mass" that overwhelms the sparse spatial features (pawn positions).
* **Fix**: Reduce CNN input channels from 11 to 6 (retaining only pawn positions, wall placements, and path masks). Concatenate the 5 scalar features directly into the fully connected layer of the value and policy heads.

### Root Cause 2: Unmasked Cross-Entropy (The Second Collapse)
During our test runs after fixing the CNN trunk, we noticed the model collapsed a second time around Epoch 42. The value loss plummeted to ~0.20, but the draw rate hit 100%. The policy network had again learned to output a constant bias favoring North moves (cosine similarity `1.0`), completely ignoring the board state.
* **Why**: Softmax was computed over all 140 actions. Because the model was not penalized for assigning high probability to *invalid* North moves, it never learned to differentiate between valid paths and blocked paths. The MCTS targets concentrated heavily on valid North moves initially, and the network lazily generalized this to *all* states.
* **Fix**: Apply a valid move mask to the policy logits before calculating `log_softmax` in the training loop. We updated `run_actor.py` to extract the absolute valid move mask from the C++ `QuoridorGame`, mapped it to the network's perspective space using `map_action_to_index_perspective`, and saved it alongside the self-play dataset. In `train_alphazero.py`, we apply a `-1e9` penalty to invalid logits.

### Root Cause 3: High Initial Learning Rate & No Gradient Clipping
`lr = 0.001` with `Adam` on a 10-block CNN is too aggressive, causing the representation to collapse before learning generalizable features.
* **Fix**: Reduce initial learning rate to `0.0003`, and add gradient norm clipping (`max_norm = 1.0`).
